# DualQuantPitch

Two granular pitch shifters turn your input into gritty harmonies, smears and
metallic textures on the Workshop Computer. Small pitch shifts give chorus-like
movement; larger shifts bring out the rough, lo-fi character. Try it on drones,
ambient patches, glitch sounds, tape-like pitch effects or feedback loops.

Main shifts both outputs together. X and Y set their individual pitch offsets,
and the two CV inputs let you modulate them independently. Put the switch in
Middle to snap the shifts to chromatic semitones.

## Features

- Two independent pitch-shifted audio outputs
- CV control of each pitch offset
- Optional chromatic pitch quantisation, with LED feedback
- Pitch CV outputs
- Overlapping grains with linear interpolation and triangle windows

# Controls

| Control                | Function                                 |
| ---------------------- | ---------------------------------------- |

| X knob                 | Pitch offset for output A                |
| Y knob                 | Pitch offset for output B                |

# Architecture

This README was originally generated by an LLM.

## Circular Buffer

Incoming audio is written into a shared 2048-sample circular buffer.

Both pitch shifters read from this buffer independently using fixed-point read heads.

Power-of-two buffer sizing allows efficient wrapping using bitmask operations instead of modulo arithmetic.

```cpp
static const int32_t BUFFER_SIZE = 2048;
static const int32_t BUFFER_MASK = BUFFER_SIZE - 1;
```

---

## Fixed-Point Format

The DSP engine uses Q16.16 fixed-point arithmetic.

* Upper 16 bits: integer component
* Lower 16 bits: fractional component

Examples:

| Value  | Meaning |
| ------ | ------- |
| 65536  | 1.0     |
| 32768  | 0.5     |
| 131072 | 2.0     |

Pitch values use Q8.8 fixed-point semitone representation.

---

## Granular Playback

Each output continuously reads through the delay buffer at a variable playback rate.

Read heads are periodically reset behind the write head to create overlapping grains.

This keeps the read heads from drifting indefinitely and gives the sound its granular texture.

---

## Interpolation

Linear interpolation smooths playback between adjacent samples.

```cpp
sample = s1 + (((s2 - s1) * frac) >> FP_SHIFT);
```

64-bit intermediate multiplication is used to avoid overflow.

---

## Grain Window

Each grain uses a triangle amplitude envelope.

This reduces hard discontinuities at grain boundaries and helps minimise clicks.

The implementation uses shift operations instead of integer division for ISR efficiency.

---

# Quantiser

The quantiser uses fixed-point chromatic rounding.

Pitch values are represented in Q8.8 semitone format.

Chromatic rounding also handles negative semitone values.

---

# Playback Ratios

Pitch shifting uses a precomputed ratio lookup table.

This avoids expensive floating-point operations such as `powf()` inside the ISR.

The ratios are approximate and musically tuned.

---

# Performance

Both pitch shifters run inside the 48 kHz audio interrupt on the RP2040. The
system clock is set to 144 MHz to leave headroom for the DSP. Processing uses:

- Fixed-point arithmetic and precomputed lookup tables
- A shared, power-of-two circular buffer with bitmask wrapping
- Shift operations for grain envelopes
- No floating-point calculations, heap allocation or blocking operations
- No modulo operations or expensive transcendental maths in the hot paths

These choices keep CPU and memory use low and interrupt timing predictable.

---

# Audio Character

Expect smearing around transients, grain-overlap modulation and metallic
artefacts. Small intervals can sound like chorus; extreme shifts can become
unstable. The granular texture is part of the sound.

---

# Safety Notes

The DSP engine includes:

* startup buffer initialisation
* bounded circular addressing
* overflow-safe interpolation
* saturated output clamping
* deterministic ISR execution

All processing is designed to remain ISR-safe.
