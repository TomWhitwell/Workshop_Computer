# Departures 0.1.0 — build and verification report

Built on 7 November 2026, branch `codex/departures-prototype`.

## Firmware

- Target: RP2040, `PICO_BOARD=pico`, default 2MB flash layout; also fits 16MB cards.
- Pico SDK 2.3.0 (revision `98a542c1a62fb549ffb5d66a3e5892b06276b670`); ARM GNU Toolchain 15.2.Rel1 / GCC 15.2.1.
- CMake Release, application `-O3`, C++17, `copy_to_ram`.
- ComputerCard 0.4.0, vendored unchanged from the existing local cards.
- CPU: 192MHz, core voltage 1.15V; crystal startup multiplier 64.
- No USB stdio, flash writes or external sample storage.
- Linker: FLASH 98,560 bytes, RAM 104,040 of 262,144 bytes, plus a 2,048-byte
  core stack in SCRATCH_Y. The FLASH count is the stored RAM image as well as
  the boot code; RAM is the corresponding runtime allocation.
- UF2: 197,120 bytes, 385 blocks. Every block's magic numbers, RP2040 family,
  size, sequence, flash range and uniqueness were checked. Reconstructed
  payload matches `build/Departures.bin`.
- Packaged firmware: `uf2/Departures_0.1.0.uf2`; digest in
  `uf2/SHA256SUMS.txt`; distribution notices beside it.
- SHA-256: `60979e3e73b924bfc1ef88a015f6f1937512a9396a27897530140de3e03d1986`.
  This is identical to the hardware-tested 0.1.0-prototype image.

## Functional and audio checks

The same engine used by firmware was compiled with Apple Clang 21, AddressSanitizer
and UndefinedBehaviorSanitizer. All host checks passed:

- Autonomous playback, melody and bass events, and automatic chord changes.
- Hold prevents automatic harmony changes; held Down advances only once.
- External clock replaces the internal clock, stops new beats when stopped,
  and resumes internal playback when disconnected.
- External chord advance overrides Hold; a disconnected input edge is ignored.
- Positive/negative octave transposition and return to zero.
- 10ms melody trigger with pitch settling delay.
- Seeded playback produces identical audio sample by sample.
- Two-minute stress sequence with full-scale audio input, extreme knob/CV
  values and rapid clocks/chord requests; no sanitizer failures or output
  range violations.
- Maximum-feedback space drains after removing its input, with no persistent
  DC buildup or oscillation.

A deterministic 90-second, 48kHz, stereo 16-bit render is generated by
`make -C test preview`. It contains 75 beats, 117 bell strikes and three chord
changes. Numerical inspection found no hard-clipped output samples and negligible
mean DC. This is synthetic engine output, not a physical Computer recording.

## ARM timing estimate

Unicorn 2.1.4 / Capstone 5.0.9 executed the compiled RP2040 callback over
22,000 samples, including startup and a stress passage with maximum activity,
brightness and effects, full-scale audio, transposition changes, fast clocks
and external chord requests. Estimated ComputerCard/IRQ overhead is 731 cycles.

| Scenario | Maximum callback | Maximum including overhead | 4,000-cycle budget |
| --- | ---: | ---: | ---: |
| Startup | 2,041 cycles | 2,772 cycles | 69.3% |
| Full activity | 2,484 cycles | 3,215 cycles | 80.4% |

The budget is 192MHz / 48kHz. Reverb runs on odd samples, echo on every fourth
sample, and sequence/control tasks occupy other sample slots. Separating these
tasks reduced the earlier worst estimate from 89.4% to 80.4%.

The model approximates instruction/peripheral timing and excludes real DMA/bus
contention. It establishes useful headroom in the exercised paths, not a measured
hardware guarantee. Physical LED 6 (code index 5) is a latched callback timing
indicator. The hardware pass below does not provide an instrumented measurement
of worst-case interrupt timing or precision CV tuning.

## Hardware verification

On 7 November 2026, Adrian reported that all suggested hardware torture tests
passed on the prototype UF2. The suggested checklist covered maximum activity,
colour and space with fast external clock/chord requests; rapid control changes;
CV extremes; external audio through the effects; clock stop, restart and
disconnect; harmony hold/advance; and repeated reset/power cycles.

No failures were reported. This records the user's hardware test result;
individual run durations, electrical measurements and exact patch settings
were not recorded. Release 0.1.0 promotes that tested binary without changing its bytes; only the
firmware filename, release documentation, metadata and packaging change.

## Local toolchain note

The `/usr/bin/make` launcher stopped at an Xcode licence prompt. The installed
Command Line Tools' direct `make` and `clang++` binaries worked without changing
licence settings. CMake was configured with
`-DCMAKE_MAKE_PROGRAM=/Library/Developer/CommandLineTools/usr/bin/make` and
`-DPICO_TOOLCHAIN_PATH=/opt/homebrew`. Host builds explicitly selected the
Command Line Tools SDK and its C++ headers.
